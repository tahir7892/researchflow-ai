# Job assessment submission — 5 required items

- [ ] **1. Working system:** Upload the GitHub repository link (or another reproducible repo), or a private local ZIP if accepted. Include `app.py`, packages, tests, sample topics, `start.sh`, README and example settings. Do not put keys in repo. Verify a fresh install and a genuine AI-mode run first.
- [ ] **2. Evaluation package:** Attach `evaluation/` as a ZIP/PDF. Include 8–12 cases (10 provided), actual observed unit test log, live source/API results, independently measured baseline/automated comparison, pass/fail scoring and three documented failure analyses with regression checks.
- [ ] **3. Case study:** Finalize `docs/CASE_STUDY_DRAFT.md` with verified user, scope, architecture, tradeoffs, measured outcomes, limitations and two-week plan. Export as PDF if submission requests.
- [ ] **4. AI collaboration note:** Finalize `docs/AI_COLLABORATION_NOTE.md` with tools actually used, corrections you personally made, how you verified the results, and decisions you personally own. Export as PDF if desired.
- [ ] **5. Demo video:** Record <=5 minutes demonstrating the real app, non-developer workflow, evaluation, failure handling, limitations and setup handoff. Upload to a link that reviewers can access.

## Must personally finish before submission
- Verify two public APIs respond from your network.
- Configure Gemini access; ensure *AI-assisted* run succeeds.
- Collect your own honest manual and automated measurements, including human review time.
- Have another person run and critique it, if possible (proxy-user test is acceptable if disclosed).
- Fill real results in the case study and evaluation sheets.
- Record and inspect the final video.

## Scoring priorities from the supplied brief
Problem scope 15%; architecture/engineering 20%; working product/reliability 20%; evaluation/learning 20%; non-developer adoption 15%; ownership/communication 10%. Aim first for an end-to-end test and rigorous evidence, not UI flourishes.
